# Anchor Read 产品定义

## 文档目的

本文档是 AnchorRead 当前产品方向的唯一主文档，用于统一产品定位、用户诉求、核心体验、能力边界和实施优先级。

项目不再只定位为“自然语言生成 Excalidraw 图”，而是在现有网页与 LLM 基础设施上，构建一套面向专业文档的 AI 阅读与记忆系统。

## 产品名称

产品名称：**Anchor Read**

产品类别：**AI Professional Document Reader**

一句话说明：**用熟悉的语言读懂陌生的专业知识。**

命名理由：

- `Anchor` 代表原文锚点、注意力锚点和已有知识锚点。
- `Read` 直接说明产品首先解决专业文档阅读，用户能够一眼识别使用场景。
- 相比 `Anchor Highlight`，`Anchor Read` 不会把能力限制在高亮，还能自然容纳贴行解释、术语记忆、概念图和闪卡。
- `AnchorRead` 已存在同类浏览器扩展；本项目采用带空格的 `Anchor Read`，并接受潜在的品牌识别风险。
- 对外展示时固定搭配 `AI Professional Document Reader`，进一步明确产品类别。

代码仓库已正式改名为 `AnchorRead`，对外展示名称统一使用带空格的 `Anchor Read`。

## 产品定位

Anchor Read 是一个专业文档 AI 阅读工作台。它在不修改原文的前提下，为文章叠加一层可开关、可保存、可逐渐减少的认知辅助层。

核心闭环：

```text
导入文章
  -> AI 抓取真正重要的原文片段
  -> 在原文位置生成白话、释义、翻译或结构说明
  -> 用户通过原文与辅助层完成阅读
  -> 标记已经理解的术语
  -> 更新术语记忆与 FSRS 状态
  -> 后续只解释仍然陌生或已经遗忘的内容
  -> 按需生成概念图和闪卡
```

## 真实诉求与解决方案

| 真实诉求 | 产品解决方案 |
| --- | --- |
| 专业文档太长，不知道哪些必须读 | 识别核心、支撑、背景、例子和可跳过内容，优先呈现核心原文 |
| 看到了关键句，但术语和抽象表达造成理解阻力 | 把陌生词义自然替换进原句，生成可连续阅读的白话理解层 |
| 摘要脱离原文，难以判断是否可信 | 所有重点和解释都绑定原文位置，随时可以对照原文 |
| 每次都解释相同术语，信息冗余 | 记录已掌握、学习中和待复习术语，让辅助层随掌握程度渐隐 |
| 理解后仍然容易遗忘 | 将术语与知识点进入 FSRS 复习流程 |
| 理解了局部，却看不清整体结构 | 从原文与重点中提取概念关系，生成可编辑的 Excalidraw 图 |

## 核心产品原则

### 1. 以熟代新

系统优先使用用户熟悉的经验、表达和已掌握术语解释新概念。目标不是永久回避专业术语，而是先建立熟悉含义与专业术语之间的连接。

### 2. 原文不被覆盖

AI 结果属于辅助层。原文必须保持完整、可见和可追溯，不允许将模型改写直接写回并冒充原文。

### 3. 解释贴近阅读位置

重点、白话和术语释义应出现在对应原文附近，避免用户在文章、聊天窗口和摘要之间反复切换。

### 4. 辅助层逐渐退出

理解层按以下阶段逐步收缩：

```text
完整白话 -> 术语与白话连接 -> 专业术语优先 -> 不再显示解释
```

用户最终应能直接阅读专业原文，而不是长期依赖 AI 改写。

### 5. 先理解，再结构化和记忆

高亮与贴行理解是主流程；概念图和闪卡是阅读后的下游能力，不应抢占阅读界面的主要注意力。

## 目标用户与典型场景

目标用户是需要阅读陌生或高密度专业内容的人，包括产品经理、开发者、研究人员、学生和跨领域学习者。

典型场景：

- 阅读 API、架构、协议或产品设计文档，快速找到必须遵守的核心约束。
- 阅读跨领域材料，用已有经验理解陌生术语和抽象概念。
- 阅读英文资料，在原文下方获得贴行中文译义。
- 阅读充满行业黑话的材料，直接看到对应的真实动作和具体含义。
- 在完成阅读后生成概念关系图和复习卡片。

## 核心阅读体验

### 快读：抓重点

AI 从全文中逐字摘取重要片段，并区分其阅读角色：

- 核心观点或关键约束。
- 概念与定义。
- 支撑论据、数据或例子。
- 结论与推断。
- 背景或可跳过信息。

高亮必须绑定原文连续片段，不能使用模型自行改写的文本定位。

### 细读：贴行理解

用户可以对全文批量生成，也可以只对选中的句子按需生成：

- 白话解析。
- 翻译。
- 通用释义。
- 去黑话行动说明。
- 结构与主干提取。
- 专业表达转换。

结果使用结构化数据保存：

```json
{
  "display": "显示在原文附近的一句自然结果",
  "mappings": [
    {
      "source": "逐字来自原文的词或短语",
      "target": "熟悉释义、真实动作或译义",
      "note": "简短解释"
    }
  ]
}
```

`display` 应像把释义自然替换进句子后的阅读结果，不能只是词典式地罗列“某词是什么意思”。

### 阅读显示模式

产品必须提供三个互斥显示模式：

- 原文 + 辅助：默认模式，用于对照理解。
- 仅原文：隐藏全部 AI 辅助。
- 仅辅助：在需要时快速阅读白话或译文层。

### 理解与渐隐

每条可学习的解释都提供“懂了”操作。用户确认理解后：

- 推进当前解释的理解等级。
- 将术语及其熟悉释义写入术语记忆。
- 更新 FSRS 状态和下次复习时间。
- 后续生成 Prompt 时传入已掌握和待复习术语。
- 对已掌握术语减少或停止重复解释。

## 功能范围

### V1：阅读闭环

V1 必须完成以下能力：

1. 粘贴或导入 Markdown、TXT 文章。
2. 保存原文、标题和阅读会话。
3. 全文自动抓重点，并在原文中精确定位。
4. 按行、段落或内容块生成阅读辅助。
5. 支持白话、翻译、通用释义和去黑话模式。
6. 保存 `display + mappings` 结果。
7. 支持原文与辅助层三种显示模式。
8. 支持单条重新生成、折叠和“懂了”。
9. 建立术语记忆并把掌握状态反馈给后续 Prompt。
10. 刷新页面后可以恢复文章及已有解释。

### V1.1：结构化理解

- 从文章和重点中提取概念及关系。
- 将概念网络转换为 Excalidraw 元素。
- 支持从概念节点回到原文来源。

### V1.2：长期记忆

- 从重点、术语和概念生成原子闪卡。
- 使用 FSRS 安排复习。
- 统一术语记忆与闪卡复习状态，避免两套彼此隔离的记忆系统。

## 核心数据对象

| 对象 | 作用 |
| --- | --- |
| Document | 保存文章、标题、来源和处理状态 |
| DocumentSlice | 表示行、段落或 Markdown 内容块 |
| AttentionAnchor | 保存核心主张、关键原句、阅读角色和重要度 |
| InterlinearGloss | 保存贴行显示结果及生成模式 |
| LexicalMapping | 保存原词与熟悉释义之间的精确映射 |
| TermMemory | 保存术语、熟悉锚点、掌握状态和来源 |
| ReviewState | 保存 FSRS 调度数据 |
| ConceptGraph | 保存概念、关系及其原文证据 |

## 两个项目的边界

### Anchor Gloss

Anchor Gloss 是认知模型、Prompt 和交互逻辑的来源。应迁移的内容包括：

- 全文重点识别。
- 行、段、块切片策略。
- `display + mappings` 输出协议。
- 原文与辅助层显示模式。
- 理解等级和脚手架渐隐。
- 术语记忆与 FSRS 反馈。
- 相同切片和生成模式的结果复用。

不直接迁移 Obsidian 专有实现，包括 `TFile`、Vault、CodeMirror Decoration、评论仓库和 Markdown 高亮写回机制。

### AnchorRead

AnchorRead 是网页产品的实现基础。继续复用：

- Next.js 16 和 React 19 页面框架。
- OpenAI、Anthropic 及兼容 API 调用。
- 客户端配置与访问密码鉴权。
- 流式 SSE 基础能力。
- 文件导入。
- Excalidraw 画布。

当前页面结构仍以图表生成器为中心，后续应围绕文档阅读状态拆分，而不是继续把所有状态堆叠在 `app/page.js` 中。

## 当前实现评估

本地未提交改造已经完成：

- 文章粘贴和 Markdown/TXT 导入。
- 全文摘要和四级静态高亮。
- 高亮原文匹配。
- 概念关系图生成。
- 闪卡生成、浏览器本地存储和轻量 FSRS 复习。

与产品定义相比仍缺少：

- 行、段、块切片与批量贴行解释。
- 选中句子的按需解释。
- `display + mappings` 词义替换模型。
- 原文、辅助和对照显示模式。
- 单条结果缓存、流式展示和重新生成。
- “懂了”驱动的理解等级变化。
- 术语记忆与渐隐 Prompt。
- 可恢复的文档阅读会话。
- 术语记忆与闪卡状态统一。

## 验收示例

原文：

> 服务端采用 at-least-once delivery，因此消费者必须保证处理逻辑具有幂等性。

白话辅助：

> 服务端采用「消息允许重复但不能丢失」的投递方式，因此消费者必须保证「同一消息重复处理也不会产生额外影响」。

系统同时保存：

- `at-least-once delivery` -> `消息允许重复但不能丢失`
- `幂等性` -> `同一消息重复处理也不会产生额外影响`

验收标准：

1. 用户能直接看到这句话是否属于核心约束。
2. 白话结果显示在对应原文附近。
3. 点击映射可以定位和强调原词。
4. 用户可以随时切回仅原文。
5. 用户标记“幂等性”已理解后，后续文章不再重复给出完整白话解释。
6. 术语到期后，系统重新提供短提示或进入复习。

## 非目标

- 不把产品做成通用聊天机器人。
- 不用摘要替代原文阅读。
- 不在 V1 追求 PDF、OCR 或复杂协作编辑。
- 不让概念图和闪卡阻塞阅读闭环交付。
- 不直接照搬 Anchor Gloss 的 Obsidian UI 和存储实现。

## 当前决策

- 产品名称使用 `Anchor Read`，对外类别说明使用 `AI Professional Document Reader`。
- 产品中心从图表生成调整为专业文档阅读与认知脚手架。
- 默认阅读模式为“原文 + 辅助”。
- 全文批量生成与选中内容按需解释同时存在。
- 原文永不被 AI 结果永久覆盖。
- 下一阶段优先完成 V1 阅读闭环，再继续扩展概念图与闪卡。
