# AnchorRead 部署与发布

## 发布原则

提交、同步和部署是同一条发布链上的三个可核对节点：

1. 本地提交：工作区必须干净，提交信息说明功能。
2. Git 同步：提交推送到 `origin/main`，确认远端哈希与本地一致。
3. 服务器部署：服务器拉取同一个提交，构建同哈希 Docker 镜像，重启容器并检查线上地址。

不要只凭“已经 push”判断线上已经更新。线上版本必须以容器镜像标签和健康检查结果为准。

## 一键发布

在仓库根目录运行 PowerShell harness：

```powershell
.\scripts\deploy-server.ps1 -Push
```

脚本默认使用以下配置：

- SSH 别名：`lcayun-1panel`
- 服务器项目目录：`/opt/anchorread`
- 分支：`main`
- 容器：`anchorread`
- 服务器本机端口：`127.0.0.1:3001`
- 线上检查：`https://anchorread.flowguide.cc/`

SSH 别名和密钥只保存在本机 `~/.ssh/config`，不会写入仓库。Cloudflare 只负责域名代理；本次应用容器发布不需要把 Cloudflare Token 放进脚本。

## Harness 做什么

`scripts/deploy-server.ps1` 会依次：

1. 拒绝未提交的工作区。
2. 检查 `origin/main` 是否包含当前提交；传入 `-Push` 时先推送。
3. SSH 到服务器拉取并切换到精确提交。
4. 构建 `anchorread:<commit>` 镜像。
5. 用临时端口启动候选容器并做本机 HTTP 检查。
6. 停止旧容器、启动新容器，并再次做本机检查。
7. 失败时自动恢复带有 `rollback-<short-commit>` 名称的旧容器。
8. 从本机请求线上 URL，并在 URL 上附加提交短哈希避免复用旧缓存。

默认会保留上一版回滚容器和旧镜像，确认稳定后再按需清理：

```powershell
ssh lcayun-1panel "docker ps -a --filter name=anchorread"
ssh lcayun-1panel "docker images anchorread"
```

## 常用参数

不希望脚本自动 push 时，省略 `-Push`；此时远端必须已经包含当前提交：

```powershell
.\scripts\deploy-server.ps1
```

指定其他 SSH 别名、域名或端口：

```powershell
.\scripts\deploy-server.ps1 `
  -SshTarget my-server `
  -HealthUrl https://example.com/ `
  -HostPort 3001
```

仅完成服务器构建和切换、不从本机请求域名时：

```powershell
.\scripts\deploy-server.ps1 -SkipHealthCheck
```

## 故障处理

- 本地工作区不干净：先提交或清理，不要让脚本猜测哪些文件应该上线。
- 远端同步失败：检查 GitHub 网络和 `origin` 地址，再重新运行 `-Push`。
- Docker 构建失败：旧容器不会被切换；修复后重新运行。
- 候选容器检查失败：脚本会删除候选容器，旧容器保持线上服务。
- 新容器切换后检查失败：脚本会删除新容器并启动旧回滚容器。
- 域名检查失败：先检查 Cloudflare/OpenResty 转发和缓存；服务器本机检查仍然是部署是否成功的第一证据。

当前线上服务的应用容器端口是 `127.0.0.1:3001`，不要直接把容器暴露到公网；公网入口由现有 OpenResty 与 Cloudflare 配置负责。
