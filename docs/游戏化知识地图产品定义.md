# 游戏化知识地图产品定义（草案）

## 文档目的

本文档是 Anchor Read 的 V2 方向草案，定义"游戏化职业知识地图"的产品定位、核心体验、数据模型与实施边界。它不是当前执行文档：V1 阅读闭环与 V1.1 / V1.2 交付之前，本文档只用于方向锁定与需求储备。

主文档为 [[Anchor Read 产品定义]]，本文档与其冲突时以主文档为准。

## 产品名称（候选）

- 候选 A：**Anchor Skill**，作为 Anchor Read 家族中的独立模块名。
- 候选 B：**成长地图**，作为 Anchor Read 内嵌功能名，不另立品牌。

暂定使用"游戏化知识地图"作为内部工作名，正式命名待用户确认。

## 产品定位

把一套职业能力体系（首个样例：产品经理知识地图）建模为带前置依赖的技能树，用户在 Anchor Read 中阅读教材、完成考核、抵抗遗忘，像升级打怪一样逐点点亮技能树。

一句话说明：**把职业技能地图变成一张可打怪升级的地图。**

核心闭环：

```text
选择职业知识地图
  -> 查看技能树与当前已点亮节点
  -> 进入解锁的技能点，阅读绑定教材（Anchor Read 阅读闭环）
  -> 通过"懂了"确认、闪卡考核与挑战题验证掌握
  -> 技能点点亮，获得经验与等级
  -> 解锁后续技能点与能力域 Boss
  -> FSRS 到期复习作为日常任务，防止技能熄灭
```

## 选型结论

本方向在既有项目中做过选型对比，结论如下：

| 能力要素 | AnchorRead | 现有知识博客站点 |
| --- | --- | --- |
| 掌握度评估（打怪判定） | 已有"懂了"交互、理解等级、FSRS 闪卡考核 | 无 |
| 掌握状态机 | 已有 TermMemory + ReviewState | 无 |
| 概念关系图 | 已有 ConceptGraph + Excalidraw 画布 | 有 D3 图谱，但是 wiki 静态展示 |
| 用户账号与持久进度 | 缺，需补 | 已有 Supabase Auth + Postgres |
| AI 能力 | 已有完整 LLM 通道 | 无 |

判断依据：这套产品最难的部分是"如何验证用户真的学会了"，即掌握判定与长期记忆追踪，AnchorRead 已经建好该核心；知识博客站点只有地图皮肤，没有游戏引擎。在其上重建学习引擎的成本高于在 AnchorRead 上补账号与持久化。

外部内容与组件的角色降级为补充源：

- 既有博客文章库作为第一批"关卡教材"的导入来源。
- 其 D3 知识图谱组件作为技能树可视化的参考实现。

## 真实诉求与解决方案

| 真实诉求 | 产品解决方案 |
| --- | --- |
| 职业技能体系庞杂，不知道从哪学起 | 技能树显式呈现能力域与技能点，前置依赖决定学习顺序 |
| 学完不知道自己会不会 | 每个技能点绑定考核：闪卡通过率 + AI 挑战题，达标才点亮 |
| 学完就忘 | FSRS 到期复习转为每日任务，复习断档触发技能"生锈"提示 |
| 学习缺少持续动力 | 经验值、等级、连击、Boss 战提供短中长期反馈 |
| 不同职业想复用同一套机制 | 知识地图是可配置数据，不写死在代码里 |

## 核心产品原则

### 1. 掌握判定优先于装饰性游戏化

经验值、徽章、特效都必须挂在真实的掌握证据上：阅读完成、"懂了"确认、闪卡考核、挑战题通过。不允许通过纯点击刷经验升级。

### 2. 地图是数据，不是界面

职业 → 能力域 → 技能点 → 前置关系全部是可编辑的结构化数据。新增一个职业知识地图应只需导入数据与教材，不改代码。

### 3. 阅读闭环不被游戏层打断

游戏化是阅读闭环的下游消费层。技能地图页面与阅读页面分离，阅读过程中只出现轻量的掌握确认，不出现弹窗式游戏反馈。

### 4. 遗忘是一等公民

技能点亮不是终点。FSRS 状态回退会反映到技能树视觉上（点亮 → 生锈 → 待重燃），复习行为是维持技能的主要玩法。

### 5. 不造新轮子

调度沿用 FSRS，考核沿用闪卡系统，概念图沿用 ConceptGraph，持久化复用既有站点已验证的 Supabase 接入方式。

## 目标用户与典型场景

首个目标用户是想系统补齐职业能力的人，首个样例地图为产品经理知识地图。

典型场景：

- 转岗产品经理，按技能树从"用户调研"开始逐点学习。
- 每天花 15 分钟清到期复习卡，维持连击与技能亮度。
- 学完一个能力域后挑战 Boss 综合题，通过后解锁下一能力域。
- 导入自己行业的知识地图，把自己的教材挂到技能点上。

## 核心玩法设计

### 技能树

- 三级结构：职业 → 能力域 → 技能点。
- 技能点之间用 `prerequisite` 边表达前置依赖；前置未点亮时技能点显示为锁定。
- 技能点状态机：`锁定 -> 解锁 -> 学习中 -> 点亮 -> 生锈 -> 待重燃`。
- 生锈与待重燃由 FSRS 到期与复习失败驱动，不是定时装饰。

### 打怪判定

一个技能点"点亮"需要同时满足：

1. 绑定教材完成阅读闭环（重点覆盖与"懂了"确认达到阈值）。
2. 绑定闪卡近期考核通过率达标。

两项阈值在 V2 定稿前保持可配置。

### Boss 战

每个能力域设一个 Boss：由 AI 基于该域技能点的教材与闪卡生成综合挑战题（简答 + 判读 + 场景决策）。通过 Boss 后解锁相邻能力域，并获得称号。

### 经验与等级

- 经验来源仅限真实掌握行为：首次点亮技能、通过考核、完成到期复习、通过 Boss。
- 等级仅由经验累计，无付费与无社交捷径。
- 连击（streak）按连续天数完成到期复习计算，断档不清零等级，只重置连击。

### 每日任务

每日任务即到期 FSRS 复习卡清单，附当日新解锁技能点提示。不提供与掌握无关的刷分任务。

## 功能范围

### V2.0：技能树与掌握判定

1. 技能树数据模型与首个产品经理知识地图数据。
2. 技能树页面：三级结构、锁定/点亮状态、前置解锁。
3. 技能点绑定教材（Document）与闪卡集。
4. 点亮判定：阅读完成阈值 + 闪卡通过率阈值。
5. Supabase 账号与云端持久化（替换 localStorage 作为主存储，本地保留离线缓存）。

- 经验值、等级、连击。
- 技能生锈与待重燃状态及对应复习引导。
- 每日任务视图（到期复习清单）。

### V2.2：Boss 战与扩展

- AI 生成能力域综合挑战题。
- 称号与能力域通关记录。
- 自定义知识地图导入（JSON/YAML）。

## 核心数据对象

| 对象 | 作用 |
| --- | --- |
| KnowledgeMap | 一个职业知识地图：能力域与技能点的集合及版本 |
| SkillDomain | 能力域：包含技能点、Boss 配置与解锁条件 |
| SkillNode | 技能点：前置依赖、绑定教材、绑定闪卡集、点亮阈值 |
| UserSkillState | 用户对某技能点的状态、点亮时间与掌握证据 |
| UserProgress | 用户经验、等级、连击与称号 |
| BossChallenge | AI 生成的综合挑战题、作答记录与判定结果 |

复用现有对象：Document、TermMemory、ReviewState、ConceptGraph。ConceptGraph 边类型扩展 `prerequisite` 即可承载技能树结构，不另建平行图模型。

## 与现有能力的边界

### 与 V1 阅读闭环

技能点教材就是普通 Document，阅读、重点、贴行解释、"懂了"全部沿用 V1 能力，不为游戏层单独造阅读逻辑。

### 与 V1.2 闪卡

闪卡生成与 FSRS 调度不变；游戏层只读取复习与考核结果换算经验，不修改调度算法。

### 与外部内容源

只取内容与组件参考，不做服务合并：

- 文章导入走 Anchor Read 现有导入通道。
- D3 图谱代码可移植为技能树可视化备选，Excalidraw 画布保留为概念图出口。

## 前置依赖与排期约束

- 必须等 V1 阅读闭环与 V1.2 长期记忆交付后再启动 V2.0。
- Supabase 接入需要新建项目或复用既有站点的 Supabase 实例，二者取一，列入待确认项。
- 首个产品经理知识地图的数据来源与授权需单独调研，不得直接抓取第三方付费内容。

## 验收示例

场景：学习"需求分析"能力域下的技能点"用户访谈"。

1. 技能树中"用户访谈"因前置"用户调研基础"已点亮而处于解锁状态。
2. 用户进入该技能点，打开绑定的教材文章，走 Anchor Read 阅读闭环。
3. 阅读完成度与"懂了"确认达到阈值后，系统提示进行闪卡考核。
4. 近期闪卡通过率达到阈值，技能点点亮，经验增加，相邻技能点"访谈提纲设计"解锁。
5. 两周后相关闪卡到期未复习，技能点显示为生锈，每日任务中出现对应复习卡。
6. 完成复习后生锈解除，连击恢复累计。

## 非目标

- 不做社交对战、排行榜竞争与付费抽卡类机制。
- 不在 V2.0 做多职业地图，先跑通产品经理一张图。
- 不做移动端专属客户端。
- 不让游戏化反馈侵入阅读界面主体注意力。
- 不新建独立仓库；本方向在 AnchorRead 仓库内演进。

## 待确认项

1. 模块命名：Anchor Skill 还是内嵌"成长地图"。
2. Supabase 实例：新建还是复用既有站点的实例。
3. 产品经理知识地图的初版数据来源（自建大纲 / 公开资料整理）。
4. 点亮阈值的具体数值（阅读完成度、闪卡通过率）。
